---
title: Verification
description: How a download is checked before it is used.
---

A release usually has one file per platform and package format. `Release.asset(Pattern)` picks the one whose whole name matches a pattern, such as `app-.*-windows-x64\.zip`. If more than one matches, it throws rather than guess.

`Downloader.download(release, asset, folder, progress)` loads the file into a new temporary file in `folder` and checks it against a SHA-256 checksum. The checksum is the one the source reports, which GitHub does for its assets, or else the one a checksum file of the same release lists, in one of two ways:

- **One file for all:** `SHA256SUMS`, `SHA256SUMS.txt`, or a file whose name ends in `checksums.txt`, in the format `sha256sum` writes.
- **One file per file:** the file's name with `.sha256` appended, such as `app.zip.sha256` for `app.zip`, with the line `sha256sum` writes for it or the checksum alone. A line that names another file, or anything that is not a SHA-256 checksum, gives no checksum.

If a release has both and they disagree, nothing is downloaded. Only a file that matches is returned, as a `Download` with its checksum, which the helper checks again before it applies the file. If no checksum is known, nothing is downloaded; if the file does not match, it is deleted and the call throws an `IOException`.

- **Progress:** `progress` is told how many bytes have arrived, each time more do. `Asset.size()` is the total.
- **Cancelling:** interrupt the thread that runs the download, for instance with `Future.cancel(true)`. The call throws an `InterruptedIOException` and leaves no file behind. A download that sends nothing for 30 seconds fails as well.
- **Private repositories:** `new Downloader(source)`, given a `GitHubSource` with a token, downloads the files of a private repository through GitHub's API. The token goes only to the API, never to where the API redirects, such as GitHub's CDN. `new Downloader()` sends no token. If the repository was renamed, give the source its new name: the API redirects the old one, and the redirect gets no token. Given a `GiteaSource` with a token, it downloads the files from the instance with the token, and from where the instance redirects, such as to object storage, without it.
- **Transport:** files are downloaded over https only, or from this machine. Redirects are followed from https to https only. A download from this machine follows none, except the API's one redirect, with a token, to this machine. A checksum file whose own checksum the source reports must match it before its entries are used.

The checksum protects against broken and altered downloads, as long as it comes from a place the download does not: GitHub reports it through its API. Gitea and Forgejo report none, so there the checksum file comes from the same instance as the file: it catches a broken download, not one the instance alters.

## Not implemented yet

If the app configures an Ed25519 public key, the download must also carry a valid signature made with the matching private key; without one it is rejected. The signature protects against a release that someone other than the app's authors published, for instance through a stolen account token.
